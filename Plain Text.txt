






Organização do Projeto O Sistema de Gerenciamento do Natal Solidário será desenvolvido por todos os integrantes do grupo. Após a divisão das funções, cada integrante ficará responsável por sua parte, sempre mantendo alinhamento com os demais. Este documento será utilizado para organizar ideias, registrar conclusões, definir ações e acompanhar o desenvolvimento do projeto. Organização por Cores Cada integrante deverá utilizar uma cor definida para sua função, facilitando a identificação das contribuições. Exemplo: Branco será utilizado para assuntos oficiais e gerais, enquanto o vermelho claro será utilizado por Lorenzo, violeta para Carlos. Sistema Base O projeto será desenvolvido a partir do sistema criado por Thiago e PH no ano passado. A versão existente servirá como base para as novas funcionalidades e melhorias. GitHub Todas as atualizações serão realizadas pelo GitHub. As alterações deverão ser avaliadas pelo grupo antes de serem oficialmente incorporadas ao projeto original. Passo a Passo
 O Liceu entra em contato com a escola e define a quantidade de cestas que será destinada a ela.
 A escola selecionada realiza o cadastro das famílias que receberão as cestas.

 Durante o evento, é registrado o recebimento da cesta pelo responsável.

Valores a Receber
 O valor unitário da rifa deve ser totalmente editável pelo administrador.
 O sistema deve calcular automaticamente o valor esperado. (para cada turma, inclusive os das rifas entregues a mais)
 Fórmula padrão:
Quantidade de rifas vendidas × Valor unitário = Valor a receber
 Permitir configurar:
 Valor da rifa
 Percentual destinado à turma
 Percentual destinado à organização
 Prazo para pagamento
 Valor mínimo de prestação de contas
 Todos esses valores devem ser editáveis pelo administrador.

Controle das Rifas *esta parte está fixa e exata não deve ser mudada em nada, considerada a parte central de tudo*
O sistema deverá realizar o controle das rifas por lotes entregues às turmas, não sendo necessário identificar ou acompanhar individualmente cada rifa ou aluno.
Cada lote deverá possuir um status que permita acompanhar sua situação, como:
Disponível — lote disponível para ser entregue.
Entregue à turma — lote entregue ao líder da turma.
Em andamento — turma está realizando as vendas.
Aguardando prestação de contas — período de vendas encerrado ou data de prestação atingida.
Prestação realizada — líder informou os resultados do lote.
Com divergência — existem diferenças entre os valores ou quantidades informados e os valores esperados.
Em atraso — a prestação de contas não foi realizada dentro da data estabelecida.
Finalizado — prestação conferida e lote encerrado.
Cancelado — lote cancelado pelo responsável.
Para cada lote, o sistema deverá registrar:
Turma responsável
Líder responsável
Quantidade de rifas entregues
Valor unitário da rifa
Data de entrega
Data prevista para prestação de contas
Quantidade de rifas vendidas
Quantidade de rifas devolvidas
Quantidade de rifas perdidas
Valor que deveria ser entregue
Valor efetivamente entregue
Diferença entre o valor esperado e o valor entregue
Data da prestação de contas
Observações
O sistema deverá realizar automaticamente os cálculos da prestação de contas com base nas informações registradas.
Não será realizado controle individual por número de rifa ou por aluno. O controle será realizado de forma consolidada, considerando o lote entregue à turma e os resultados apresentados pelo líder na prestação de contas.
